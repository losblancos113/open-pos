# M3: Order Engine & POS Terminal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a fully functional, offline-first sales terminal for restaurants and cafés, supporting interactive floor plan table sessions, counter fast sales, real-time modifier and combo order lines, append-only order event sourcing, deterministic bills with inclusive/exclusive VAT, lossless split payments, pure offline VietQR EMVCo payloads, and 80mm thermal receipt printing.

**Architecture:** Domain logic lives in pure TypeScript modules (`src/core/order/`, `src/core/qr/`) decoupled from UI and storage. Order state is append-only event-sourced, partitioned per table session (`session_events:<branchId>:<sessionId>`) with automatic conflict union on 409 and materialized snapshots on bill closure. The POS terminal UI (`src/features/pos/`) is built on headless `@vuetify/v0` primitives styled with UnoCSS tokens.

**Tech Stack:** Vue 3 (Composition API, `<script setup>`), TypeScript strict, `@vuetify/v0`, UnoCSS (`presetWind4`), PouchDB, Vitest, Vue Test Utils.

**Spec:** `docs/superpowers/specs/2026-10-23-m3-order-pos-design.md` (and parent `docs/superpowers/specs/2026-10-20-open-pos-design.md`)

## Global Constraints

- **Pure Domain Isolation (`AGENTS.md` §2):** Everything in `src/core/` must be pure TypeScript — zero imports from `vue`, `vue-router`, or `pouchdb`.
- **Mandatory `branchId` (`AGENTS.md` §4.1):** Every document envelope must carry a non-empty `branchId`.
- **Integer Minor Units (`AGENTS.md` §4.2):** Money values are strictly integers (`VND` exponent 0, `USD` exponent 2). Never use floating-point arithmetic.
- **Deterministic Allocation (`AGENTS.md` §4.3):** Splits and percent discounts must use largest-remainder allocation; parts must sum exactly to the total.
- **`_id` Prefix Contracts (`AGENTS.md` §4.4):** Use helpers in `src/core/db/ids.ts`. Never concatenate ID strings manually.
- **UI Primitives (`AGENTS.md` §4.8):** All interactive components come from `@vuetify/v0`.
- **Token-Driven Styling (`AGENTS.md` §4.9):** Styling is strictly UnoCSS utilities derived from `src/styles/tokens.ts` (e.g., `btn-primary`, `panel-card`, `field-input`).
- **i18n Parity (`AGENTS.md` §4.6):** Every key added to `src/i18n/vi.json` must be added to `src/i18n/en.json` in the same task.

## Review Focus

The five edge cases and failure modes most likely to affect users:
1. **VietQR transfer description corruption:** Banking apps truncate or reject transfer contents with accents, lowercase characters, or special symbols. *Pinned in Task 2 & Task 4: strict uppercase alphanumeric validation matching `^POS[A-Z0-9]{3,17}$`.*
2. **Offline sequence collision between two terminals:** Two offline devices independently creating bill `0001` in branch `HQ`. *Pinned in Task 2: payment reference format `POS{branchCode}{terminalCode}{seq}` (e.g. `POSHQT010001`) guarantees global uniqueness across devices.*
3. **Split payment remainder rounding loss:** Multiple partial cash and transfer payments leaving 1₫ unpaid due to rounding. *Pinned in Task 3: exact minor unit deduction `balanceRemaining = max(0, total - sum(payments))`.*
4. **409 conflict during concurrent table ordering:** Two staff members placing lines on table B01 simultaneously. *Pinned in Task 6: event array union merging by `eventId` on 409 retry.*
5. **VietQR generated before bank account configuration:** Staff attempting to accept VietQR without an account on file. *Pinned in Task 12 & Task 13: payment modal checks bank configuration and directs staff to settings if missing.*

import { describe, it, expect } from 'vitest';
import { createMemoryAdapter } from '../../db/memory-adapter';
import { createOrderRepository } from '../order-repository';
import { formatBillNumber, formatPaymentRef } from '../numbering';
import { buildVietQrPayload } from '../../qr/vietqr';
import { generateQrSvg } from '../../qr/qr-matrix';
import { money } from '../../money';
import { assembleMenu } from '../../catalog/menu';
import type { SessionDoc, BillDoc } from '../types';

describe('M3 Acceptance: End-to-End Single-Device Cafe Sales Flow', () => {
  it('executes a complete sales cycle: open table, add items with toppings, apply discount, pay with VietQR + cash, and print bill', async () => {
    const adapter = await createMemoryAdapter();
    const repo = createOrderRepository(adapter);

    // 1. Setup Table & Area
    await repo.saveArea({ _id: 'area:hq:indoor', branchId: 'hq', name: 'Trong nhà', sortOrder: 1, createdAt: '' });
    await repo.saveTable({ _id: 'table:hq:t1', branchId: 'hq', areaId: 'area:hq:indoor', code: 'B01', name: 'Bàn 1', capacity: 4, sortOrder: 1, createdAt: '' });

    // 2. Setup Bank Account for VietQR
    await repo.saveBankAccount({
      _id: 'bank_account:hq',
      branchId: 'hq',
      bankBin: '970422',
      bankName: 'MBBank',
      accountNumber: '0901234567',
      accountName: 'NGUYEN VAN A',
      updatedAt: '',
    });

    // 3. Open Table Session & Create Bill
    const date = new Date(2026, 9, 23);
    const seq = await repo.nextSequence('hq', 'T01', '20261023');
    const billNumber = formatBillNumber('HQ', 'T01', date, seq);
    const paymentRef = formatPaymentRef('HQ', 'T01', seq);

    expect(billNumber).toBe('HQ-T01-20261023-0001');
    expect(paymentRef).toBe('POSHQT010001');

    const session: SessionDoc = {
      _id: 'session:hq:s1',
      branchId: 'hq',
      tableIds: ['table:hq:t1'],
      guestCount: 2,
      status: 'open',
      openedAt: new Date().toISOString(),
      openedBy: 'cashier-1',
      billIds: ['bill:hq:b1'],
    };

    const initialBill: BillDoc = {
      _id: 'bill:hq:b1',
      branchId: 'hq',
      sessionId: 'session:hq:s1',
      billNumber,
      paymentRef,
      status: 'draft',
      lines: [],
      discounts: [],
      surcharges: [],
      taxMode: 'inclusive',
      taxLines: [{ rateId: 'vat10', label: { vi: 'VAT 10%', en: 'VAT 10%' }, rate: 10, base: money(0, 'VND'), amount: money(0, 'VND') }],
      taxTotal: money(0, 'VND'),
      subtotal: money(0, 'VND'),
      discountTotal: money(0, 'VND'),
      surchargeTotal: money(0, 'VND'),
      total: money(0, 'VND'),
      payments: [],
      balanceRemaining: money(0, 'VND'),
      createdAt: new Date().toISOString(),
      updatedAt: new Date().toISOString(),
    };

    // 4. Add Order Line with Toppings (Phở bò 65k + Trứng 5k = 70k)
    let state = await repo.appendEvents(
      'hq',
      session._id,
      [
        {
          eventId: 'ev-1',
          type: 'LINE_ADDED',
          sessionId: session._id,
          billId: initialBill._id,
          actorId: 'cashier-1',
          deviceId: 'T01',
          payload: {
            lineId: 'l1',
            productId: 'product:pho-bo',
            nameSnapshot: { vi: 'Phở bò', en: 'Beef pho' },
            unitPriceSnapshot: money(65000, 'VND'),
            qty: 1,
            modifiers: [{ groupId: 'g1', groupNameSnapshot: 'Topping', optionId: 'o1', optionNameSnapshot: 'Trứng', priceDelta: money(5000, 'VND') }],
            addedAt: new Date().toISOString(),
          },
          createdAt: new Date().toISOString(),
          schemaVersion: 1,
        },
      ],
      { session, bill: initialBill }
    );

    expect(state.bill.total.minor).toBe(70000);

    // 5. Generate VietQR dynamic payload & SVG
    const bank = (await repo.getBankAccount('hq'))!;
    const qrPayload = buildVietQrPayload({
      bankBin: bank.bankBin,
      accountNumber: bank.accountNumber,
      accountName: bank.accountName,
      amount: state.bill.total,
      paymentRef: state.bill.paymentRef,
    });
    const qrSvg = generateQrSvg(qrPayload);
    expect(qrSvg).toContain('<svg');
    expect(qrPayload).toContain('POSHQT010001');

    // 6. Split Payment: 20k cash + 50k VietQR transfer
    state = await repo.appendEvents(
      'hq',
      session._id,
      [
        {
          eventId: 'ev-2',
          type: 'PAYMENT_ADDED',
          sessionId: session._id,
          billId: initialBill._id,
          actorId: 'cashier-1',
          deviceId: 'T01',
          payload: {
            paymentId: 'pay-cash',
            method: 'cash',
            amount: money(20000, 'VND'),
            tendered: money(50000, 'VND'),
            change: money(30000, 'VND'),
            createdAt: new Date().toISOString(),
          },
          createdAt: new Date().toISOString(),
          schemaVersion: 1,
        },
        {
          eventId: 'ev-3',
          type: 'PAYMENT_ADDED',
          sessionId: session._id,
          billId: initialBill._id,
          actorId: 'cashier-1',
          deviceId: 'T01',
          payload: {
            paymentId: 'pay-vietqr',
            method: 'bank_transfer',
            amount: money(50000, 'VND'),
            ref: state.bill.paymentRef,
            createdAt: new Date().toISOString(),
          },
          createdAt: new Date().toISOString(),
          schemaVersion: 1,
        },
        {
          eventId: 'ev-4',
          type: 'BILL_CLOSED',
          sessionId: session._id,
          billId: initialBill._id,
          actorId: 'cashier-1',
          deviceId: 'T01',
          payload: {},
          createdAt: new Date().toISOString(),
          schemaVersion: 1,
        },
      ],
      state
    );

    expect(state.bill.status).toBe('paid');
    expect(state.bill.balanceRemaining.minor).toBe(0);
    expect(state.bill.payments).toHaveLength(2);
  });
});
